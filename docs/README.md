# docs

## このディレクトリは何か

このプロジェクトのドキュメントを置く場所。文書の性格ごとにサブディレクトリを分け、各サブディレクトリの `README.md` を案内板として運用する。

## いつ読むか

- どこに何が書いてあるか分からないとき
- 新しい文書を追加するとき（どのディレクトリに置くかを決めるため）

## 文書一覧

| ディレクトリ                    | 内容                                                             |
| ------------------------------- | ---------------------------------------------------------------- |
| [`adr/`](adr/README.md)         | なぜその選択をしたか（個別判断、1 判断 = 1 ファイル）            |
| [`runbook/`](runbook/README.md) | 実作業の手順（環境構築・デプロイ・運用）                         |
| `lang/`                         | ルート `README.md` の翻訳（英語版は [`lang/en.md`](lang/en.md)） |

文書が増えたら、次の振り分けでサブディレクトリを作る。

| ディレクトリ    | 内容                                                                |
| --------------- | ------------------------------------------------------------------- |
| `specs/`        | 何を作るか（機能要件・非機能要件・スコープ）                        |
| `architecture/` | どう作るか（システム構成・全体像・CI/CD）                           |
| `strategies/`   | どう進めるか（開発・テストの方針）                                  |
| `log/`          | 実作業の経緯（時系列の作業ログ。手順そのものは `runbook/` が SSOT） |
| `knowledge/`    | ツール・プラグインの入門知識（1 ツール 1 ファイル）                 |

## 書き方

- サブディレクトリは**最初の文書を作るときに作る**。空のディレクトリを先に用意しない。`adr/` だけは、`CLAUDE.md` が一覧（`adr/README.md`）を読み込むため、最初から置く
- サブディレクトリを作ったら、同時にそのディレクトリの `README.md`（案内板）を置き、本ファイルの表からリンクする
- 案内板の構成は `.claude/rules/readme.md` に従う（`## このディレクトリは何か` → `## いつ読むか` → 一覧テーブルの順）
- 本ファイルに文書の本文を書かない。リンクで案内するだけにする
